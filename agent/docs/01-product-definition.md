# تعریف محصول

## نام کاری

**ForgePilot** — کارخانه نرم‌افزار ایجنتی، Local-first و BYOK.

## تعریف یک‌خطی

فضای کاری که درخواست طبیعی کاربر را به مشخصات، طراحی، کد، تست، پیش‌نمایش و در
نهایت یک Pull Request قابل بررسی یا استقرار تأییدشده تبدیل می‌کند — و هر ادعای
موفقیت را به یک شواهد اجرایی گره می‌زند.

## تفاوت با یک چت‌بات کدنویس

| چت‌بات | این محصول |
|---|---|
| متن تولید می‌کند | Artifact تولید می‌کند |
| «انجام شد» می‌گوید | exit code و log نشان می‌دهد |
| یک مدل | یک روتر با سیاست محرمانگی |
| بدون مرز مجوز | کلاس‌بندی ریسک و Approval |
| حافظه‌اش همان پنجره context است | چهار لایه حافظه + index مخزن |
| اجرا روی ماشین کاربر بدون ایزوله‌سازی | Sandbox با حد منابع و شبکه خاموش |

## ورودی و خروجی

**ورودی کاربر**

> «یک پلتفرم تبادل کالا با حساب کاربری، آگهی، پیشنهاد معاوضه، چت و پنل مدیریت
> بساز.»

**خروجی تحویلی**

```
delivery/
├── requirements.md            مشخصات و معیار پذیرش
├── architecture.md            معماری و ADRها
├── threat-model.md            مدل تهدید
├── source-code/               روی branch ایجنت
├── migrations/                با مسیر down
├── tests/                     همراه لاگ اجرا
├── preview/                   URL پیش‌نمایش + smoke test
├── pull-request               با خلاصه، ریسک‌ها و گزارش تست
├── security-report.md         findings با دستور verification
└── delivery-report.md         چه شد، چه نشد، چرا
```

## کاربران هدف

1. **سازنده مستقل** — ایده دارد، زمان ندارد، می‌خواهد تا PR پیش برود.
2. **تیم کوچک** — می‌خواهد کارهای تکراری (scaffold، تست، migration، CI) را
   واگذار کند.
3. **سازمان با داده حساس** — می‌خواهد مدل روی زیرساخت خودش اجرا شود و کدش هرگز
   از شبکه خارج نشود.

این سه نفر یک محصول نمی‌خواهند؛ اما یک هسته می‌خواهند. تفاوتشان در **Policy**
است، نه در کد. به همین دلیل Policy Engine یک شهروند درجه‌یک است.

## جریان کاربر

```
۱. ثبت‌نام → ساخت Workspace → انتخاب زبان، منطقه زمانی، سطح محرمانگی
۲. انتخاب حالت محاسباتی: رایگان / پولی / لوکال — با نمایش فوری اینکه چه چیزی
   عوض می‌شود (بودجه، دروازه‌ها، اجازه خروج داده) و بررسی پیش از شروع
۳. اتصال ابزارها (GitHub اول) — با نمایش scope، تاریخ انقضا، آخرین استفاده
۴. ثبت درخواست (چت + فرم ساختاریافته)
۵. پاسخ به حداکثر ۷ سؤال ضروری
۶. دریافت Plan: stack، مایلستون، تسک‌ها، مجوزها، ریسک‌ها، بودجه، rollback
۷. تأیید Plan  ← تا این لحظه هیچ بایتی نوشته نشده
۸. تماشای اجرا: تسک‌بورد، لاگ زنده، diff، رویدادها
۹. تأیید عملیات کلاس C و D (PR، deploy)
۱۰. دریافت Pull Request + گزارش تحویل
```

## MVP

**در MVP هست:**

- حساب، Workspace، نقش‌های کاربری، تنظیمات حریم خصوصی
- پروژه و درخواست متنی
- اتصال GitHub از طریق GitHub App (خواندن، branch، commit، PR)
- ایجنت: تحلیل → Plan → تأیید → اجرا → تست → PR
- Sandbox داکری: بدون شبکه، غیر root، حد CPU/RAM/زمان
- Quality gates: lint، typecheck، unit test، build، secret scan
- خروجی: diff، گزارش تست، گزارش امنیت، Pull Request
- مدل محلی با Ollama + یک ارائه‌دهنده ابری رایگان با نمایش سقف

**در MVP نیست:**

- GitLab، Bitbucket، Figma، Slack، Linear، Notion
- Browser Automation
- استقرار روی Production
- اجرای موازی چند ایجنت روی یک مخزن
- اپ موبایل و دسکتاپ (فقط PWA)
- Marketplace کانکتور

## غیرهدف‌های صریح

- جایگزینی مهندس. محصول یک PR تولید می‌کند؛ تصمیم نهایی با انسان است.
- ساخت اپ iOS امضاشده. این به محیط و حساب Apple نیاز دارد و خودکارسازی کامل آن
  در دامنه این محصول نیست.
- دور زدن محدودیت سرویس‌ها برای «رایگان‌تر» شدن.
- ذخیره رمز عبور کاربر برای هر سرویسی.
- خودکارسازی کامل بدون هیچ نقطه تأیید.

## معیار موفقیت محصول

یک Run موفق است اگر:

1. Plan تأییدشده بدون تغییر باقی مانده باشد (hash یکسان).
2. همه acceptance criteria با تست اثبات شده باشند.
3. lint، typecheck، build، test با exit code 0 اجرا شده باشند.
4. secret scan پاک باشد و finding بحرانی/بالای باز وجود نداشته باشد.
5. PR ساخته شده باشد و diff آن قابل بررسی باشد.
6. هیچ عملیات کلاس D بدون تأیید ثبت‌شده انجام نشده باشد.
7. گزارش تحویل، هر ادعا را به یک artifact لینک کرده باشد.

- رابط کاربری: فارسی پیش‌فرض با RTL کامل، `en-US` به‌عنوان زبان دوم.
- پرامپت‌های سیستمی: انگلیسی (دقت دستورپذیری بالاتر در اکثر مدل‌ها) با الزام
  صریح به پاسخ فارسی. این یک تصمیم آگاهانه است و در
  `prompts/fragments/persian-voice.md` مستند شده.
- شناسه‌های فنی، نام فایل و پیام commit: انگلیسی.
- دسترسی‌پذیری: WCAG 2.1 AA، ناوبری کامل با کیبورد، پشتیبانی screen reader.
