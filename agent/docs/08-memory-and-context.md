# حافظه و Context

ایجنت نباید کل مخزن را در هر درخواست به مدل بفرستد. نه به‌دلیل هزینه — به این
دلیل که context بزرگ دقت را کم می‌کند.

## چهار لایه

### ۱. حافظه جلسه‌ای
- پیام‌های همین گفت‌وگو
- تسک فعلی و وضعیتش
- تصمیم‌های چند دقیقه اخیر
- خطاهای همین Run

### ۲. حافظه پروژه‌ای
- stack و نسخه‌ها
- معماری و ADRها
- قوانین کدنویسی کشف‌شده توسط Repository Analyst
- ساختار مخزن
- خطاهای قبلی و راه‌حل‌هایشان
- فهرست فایل‌های حساس

### ۳. حافظه سازمانی
- الگوهای تأییدشده
- وابستگی‌های مجاز و ممنوع
- استانداردهای امنیتی داخلی
- Templateهای پروژه
- ارائه‌دهندگان مجاز

### ۴. Index مخزن
- نقشه مخزن (فایل‌ها و هدف هر پوشه)
- symbolها و signatureها
- گراف import
- endpoint های API
- تست‌ها و اینکه چه چیزی را پوشش می‌دهند
- READMEها و ADRها

## ساخت context

```
User Request
      ↓
Relevant Project Memory      (چه چیزی قبلاً تصمیم گرفته شده)
      ↓
Repository Map               (کجا چه چیزی است)
      ↓
Related Files                (فقط فایل‌های مرتبط با تسک)
      ↓
Relevant Tests               (تست‌هایی که این تغییر را می‌سنجند)
      ↓
Security Rules               (قطعه invariants + قواعد خاص پروژه)
      ↓
Task Spec + Acceptance Criteria
      ↓
Secret Redaction             ← آخرین دروازه، همیشه
      ↓
Workspace Policy Check       ← آیا این محتوا اجازه خروج دارد؟
      ↓
Final Model Context
```

## قواعد انتخاب فایل

برای هر تسک، فقط فایل‌هایی وارد context می‌شوند که:

1. در `allowedPaths` هستند، یا
2. توسط گراف import به آن‌ها وابسته‌اند، یا
3. تست مربوط به آن‌هاست، یا
4. قرارداد مشترک (schema، type، migration) را تعریف می‌کنند

هرگز: کل مخزن، همه تست‌ها، فایل‌های حساس، `node_modules`، lockfile کامل،
artifact های build.

## بودجه context

```ts
{
  contextTokens: 24000,     // ورودی Router
  // اگر بیشتر شد، به ترتیب حذف می‌شود:
  // ۱. بدنه تست‌های غیرمرتبط (فقط نامشان می‌ماند)
  // ۲. بدنه فایل‌های بزرگ (فقط signature)
  // ۳. تاریخچه گفت‌وگو (خلاصه می‌شود)
  // هرگز حذف نمی‌شود: acceptance criteria، invariants، task spec
}
```

## حافظه طولانی‌مدت

در فاز بعد، با pgvector:

- embedding روی ADRها و تصمیم‌های معماری
- embedding روی خطاهای قبلی و راه‌حل‌ها
- بازیابی شباهت برای «قبلاً این مشکل را داشتیم؟»

شرط لازم: حافظه بازیابی‌شده هم **غیرقابل اعتماد** است. یک یادداشت قدیمی نمی‌تواند
مجوز جدید ایجاد کند.

## فشرده‌سازی گفت‌وگو

وقتی طول گفت‌وگو از آستانه گذشت:

1. تسک‌های تکمیل‌شده به یک خلاصه یک‌خطی + لینک artifact تبدیل می‌شوند
2. تصمیم‌ها به `assumptions` و `confirmedRequirements` منتقل می‌شوند
3. فقط دو تسک آخر با جزئیات می‌مانند
4. `acceptanceCriteria` هرگز فشرده نمی‌شود
