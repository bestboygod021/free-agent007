# لایسنس و ملاحظات حقوقی

> این سند مشاوره حقوقی نیست. پیش از ارائه تجاری، با یک وکیل متخصص نرم‌افزار
> بررسی شود. هدف این سند این است که سؤالات درست را فهرست کند.

## سه اشتباه رایج درباره «رایگان»

1. **رایگان ≠ آزاد.** یک API رایگان ممکن است استفاده تجاری یا white-label را
   ممنوع کرده باشد.
2. **Open Source ≠ هر استفاده‌ای.** برخی لایسنس‌ها (AGPL، SSPL، BSL) در مدل
   SaaS تعهد ایجاد می‌کنند.
3. **Free Tier ≠ حق.** سهمیه رایگان یک تصمیم تجاری موقت است، نه یک قرارداد.

## n8n

n8n برای اتوماسیون داخلی و نمونه‌سازی عالی است، اما تحت **Sustainable Use
License** است، نه یک لایسنس متن‌باز معمولی. بر اساس مستندات رسمی n8n:

- استفاده داخلی با شرایطی مجاز است
- فروش محصولی که ارزش اصلی‌اش ارائه قابلیت‌های n8n یا دسترسی کاربران به محیط
  n8n باشد، ممکن است نیاز به مجوز تجاری جداگانه داشته باشد
- جمع‌آوری credential کاربران نهایی برای اتصال به حساب‌های شخص ثالث می‌تواند
  محدودیت ایجاد کند

**تصمیم معماری:** هسته Agent و Workflow را خودمان می‌سازیم. n8n فقط برای
عملیات داخلی، prototype و سناریوهای غیرعمومی.

## لایسنس مدل‌ها

«مدل باز» یک طیف است:

| نوع | نمونه وضعیت |
|---|---|
| Apache-2.0 کامل | آزاد برای استفاده تجاری |
| وزن باز با لایسنس سفارشی | ممکن است سقف کاربر ماهانه یا محدودیت تجاری داشته باشد |
| وزن باز با شرط عدم رقابت | برای SaaS ریسک دارد |
| API رایگان | شرایط سرویس، نه لایسنس نرم‌افزار |

`ModelProviderCapability.license` در `src/core/types.ts` وجود دارد تا Router
بتواند بر اساس لایسنس هم فیلتر کند، نه فقط قیمت و سرعت.

## ثبت لایسنس در محصول

- هر `ConnectorManifest` فیلد اجباری `commercialLicense` دارد
- هر وابستگی افزوده‌شده توسط ایجنت باید در `dependenciesAdded` لایسنس و دلیل
  داشته باشد
- Security Reviewer تداخل لایسنس را به‌عنوان یک finding گزارش می‌کند
- گزارش تحویل، جدول وابستگی‌ها با لایسنسشان را شامل می‌شود

## حریم خصوصی

### اصول

1. کمینه‌سازی داده — فقط آنچه برای کار لازم است
2. Local-first به‌عنوان پیش‌فرض برای داده حساس
3. رضایت صریح و per-run برای خروج داده از ماشین
4. هرگز رمز عبور خام
5. redaction پیش از هر خروج
6. دوره نگهداری مشخص و حذف واقعی

### اسناد لازم

- Privacy Policy — چه داده‌ای، چرا، کجا، تا کی، چگونه حذف
- Terms of Service — مرز مسئولیت، ممنوعیت‌ها، مالکیت خروجی
- DPA برای مشتریان سازمانی
- Sub-processor list با به‌روزرسانی عمومی

### حقوق کاربر

| حق | پیاده‌سازی |
|---|---|
| دسترسی | export کامل داده در قالب JSON |
| اصلاح | ویرایش پروفایل و تنظیمات |
| حذف | صف حذف با تأیید دو مرحله‌ای |
| انتقال | export مخزن، Plan و گزارش‌ها |
| اعتراض به پردازش | خاموش کردن حالت ابری در سطح Workspace |

## مالکیت خروجی

باید صریح مشخص شود:

- کد تولیدشده متعلق به کیست
- آیا پلتفرم حق استفاده از آن را برای آموزش دارد (پیشنهاد: **خیر**، مگر opt-in)
- چه کسی مسئول بررسی نهایی است (کاربر)
- سلب مسئولیت درباره صحت و امنیت کد تولیدشده

## ممنوعیت‌های قابل اجرا در محصول

این موارد فقط در متن شرایط نیستند؛ در `DENY_RULES` پیاده‌سازی شده‌اند:

- ساخت انبوه حساب
- دور زدن CAPTCHA و MFA
- دور زدن rate limit
- جمع‌آوری داده شخصی بی‌ارتباط با کار
- انتشار محتوای نقض‌کننده حقوق دیگران
