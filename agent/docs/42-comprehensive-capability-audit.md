## هدف و محدودیت ممیزی

این سند میان سه چیز فرق می‌گذارد:

1. **درخواست/پیشنهاد طراحی‌شده:** در `docs/`، `docs/upgrade-register.json` یا prompt pack قرارداد و معیار دارد.
2. **kernel/contract کدنویسی‌شده:** validation یا decision deterministic دارد، اما adapter durable، UI، external service، runtime یا evidence production ندارد.
3. **قابلیت ایجادشده و تأییدشده:** فقط وقتی قابل اعلام است که implementation کامل، تست مناسب و evidence واقعی در خروجی ابزار وجود داشته باشد.

منبع این ممیزی، کل artifactهای canonical فعلی repository است: `README.md`، roadmap،
`docs/upgrade-register.json`، `docs/gap-register.json`، `src/core/design-coverage.ts`،
تمام phase documents و test registry. این سند ادعا نمی‌کند که متن‌های خارج از repository
را به‌طور جادویی به یاد دارد؛ هر requirement بدون artifact باید دوباره از کاربر یا
source معتبر دریافت شود.

## Promptهای این سری

### `audit-gap-analyst`

```text
نقش: Capability Audit Analyst

تمام proposalها، gapها، design topicها و code evidence را با ID و status بخوان.
هر ادعای «ساخته‌شده» را فقط با path موجود و test/tool output معتبر بپذیر. designed_only،
partial، scaffolded و done_tested را مخلوط نکن. قابلیت‌های مشابه را duplicate نکن و
هر مورد بدون evidence را unresolved نگه دار.
```

### `next-phase-selector`

```text
نقش: Next Phase Selector

از unresolved P0/P1ها پنج فاز cohesive انتخاب کن. dependency، safety، free/local/BYOK،
privacy، human approval و production boundary را مشخص کن. فقط deterministic kernel
را در این مرحله بساز؛ external adapter را طراحی‌شده اما اجرا‌نشده علامت بزن.
```

### `audit-evidence-gate`

```text
نقش: Audit Evidence Gate

برای هر capability سه سطح را جدا گزارش کن: design artifact، kernel test و production
evidence. status را بدون command/test output تغییر نده. raw secret، CAPTCHA/MFA bypass،
bulk account creation، direct main push و untrusted execution خارج از sandbox ممنوع است.
```

## معیار خروج از این ممیزی

این ممیزی زمانی قابل کوچک‌شدن است که هر proposal به یکی از این وضعیت‌ها با evidence
مستقل برسد:

- `scaffolded`: contract و skeleton واقعی با test boundary
- `partial`: بخشی از integration واقعی، بدون ادعای production completeness
- `done_tested`: قابلیت کامل، test/evidence واقعی و acceptance criteria اجراشده

تا آن زمان `docs/42-comprehensive-capability-audit.md`، gap register و upgrade register
باید هم‌زمان به‌روزرسانی شوند؛ اضافه‌کردن کد بدون ثبت gap یا evidence قابل قبول نیست.
